# 裁判评分系统 🏅

基于 Streamlit 的裁判评分 Web 应用，支持答辩组、实操组和北京线上实操组三类裁判在线评分。

## 功能

- **裁判登录**：姓名 + 编号 + 组别选择，URL 自动记住登录状态
- **分组评分**：
  - 答辩组：大模型思路讲解/语音交互方案(30)、视觉流程(30)、机器人控制(30)、创新性/答辩流畅(10)
  - 实操组：语音交互(12)、大模型任务卡解析(34)、装配流程(24)、装配精度(30)
  - 北京线上实操组：大模型智能体(30)、VM视觉(20)、机器人仿真(20)，总分70分
- **表格式按钮评分**：每个评分项独占一行，并列出该项全部可选分值
- **实操扣分与否决**：9项扣分规则采用次数填写或规则按钮，2项否决勾选后总分归零
- **北京线上实操规则**：3项固定扣分按钮，2项否决勾选后总分归零
- **装配精度**：按钮显示偏移量及对应得分，支持小数分值
- **并发安全记录**：每次提交使用唯一 ID，远端 SHA 冲突时自动重新合并，只有 GitHub 确认保存后页面才显示成功
- **完整历史导出**：后台导出前合并 `score-data`、`main` 与本地缓存，Excel 同时包含评分记录和完整提交审计
- **移动端适配**：手机浏览器即可使用

## 快速开始

### 本地运行

```bash
# 安装依赖
pip install -r requirements.txt

# 启动应用
streamlit run app.py
```

### 部署到 Streamlit Cloud

1. 将代码推送到 GitHub 仓库
2. 访问 https://share.streamlit.io/
3. 点击 "New app" → 选择仓库 → Deploy

## 数据持久化

- 评分记录写入独立的 `score-data` 分支，避免评分提交触发应用重新部署。
- 多人同时提交时通过 GitHub 文件 SHA 进行乐观锁更新；发生冲突会重新读取、合并并重试，不会用旧整文件覆盖新记录。
- `GITHUB_TOKEN` 必须具备仓库 `Contents: Read and write` 权限。未能确认远端持久化时，评分页会显示失败并保留同一提交 ID 供安全重试。
- 后台 Excel 下载会强制刷新远端数据；远端不可用时拒绝生成可能不完整的历史文件。
